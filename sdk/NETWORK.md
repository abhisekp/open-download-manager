# Provider networking — API 2

API 1 resolvers retain no network access. API 2 introduces an optional `network_hosts` list of at most 16 exact hosts; installation still requires review of the exact signed package. A resolver invocation additionally requires explicit network approval bound to that installed package digest. Editing the input URL or selected add-on clears approval. Updates revoke prior grants. The entered URL, including query parameters, may be sent to approved hosts; the UI must explain this before invocation.

The trust boundary is an untrusted signed WASM module calling an allowlisted host function. Assets include private input links, OS credentials, files, private network services and core availability. A signature establishes key continuity, not safe code or a trusted organization. The new function supplies no cookies, OS credentials, arbitrary headers, filesystem or subprocess access. It cannot automatically add a transfer.

Host ABI: import `odm.http_get(url_ptr:i32,url_len:i32,out_ptr:i32,out_capacity:i32)->i32`. Return the byte count for a successful HTTP 200 response or -1 on refusal/failure; no partial result is exposed. Memory ranges are checked before use. Only HTTPS on port 443 and declared hosts are accepted, with no userinfo or fragment. Redirects and environment proxies are disabled. DNS results are checked against conservative private/reserved address exclusions and the connection is pinned to a checked public address; TLS continues to authenticate the declared hostname. Private, loopback, link-local, translated/tunnel and known metadata destinations are refused.

Limits: four attempts, 256 KiB per response, a 512 KiB total body budget and an eight-second API 2 VM deadline inside a twelve-second invocation deadline. API 1 retains its two-second VM limit. WASM memory remains 64 MiB and output streams remain bounded. OS-enforced worker memory containment, provider credentials, other HTTP methods, events and UI contributions remain separate acceptance gates.

Local abuse/success acceptance covers: API 1 network refusal; exact-package approval; host/port/scheme/credential/fragment refusal; private/mixed DNS and rebinding refusal without dialing; TLS hostname validation; redirect refusal; cancellation; body and request limits; memory-range validation; update/revoke behavior; real WASI request/response; and unchanged download behavior until explicit result review. Real WASI modules exercised successful HTTP/TLS request/response through original local fixtures with test-only pinned dialing and certificate roots. An actual isolated worker also refused an undeclared target before DNS and returned reviewed fixture output. The browser passed signed install/enable, host disclosure, approval revocation after link/add-on changes and each invocation, result review without automatic transfer, uninstall and unchanged core downloads. No live external provider received a private input link during these tests. These results do not establish external provider availability or compatibility.

Address policy references: [IANA IPv4 special-purpose space](https://www.iana.org/assignments/iana-ipv4-special-registry), [IANA IPv6 special-purpose space](https://www.iana.org/assignments/iana-ipv6-special-registry). These inform conservative exclusions; an address label alone does not prove routability or trust.

The transport reads one additional byte when needed to detect an oversized body and returns no partial response. Oversized/interrupted reads also consume the per-invocation budget. Input/output URL host permissions retain their existing semantics; the new network list only grants checked public HTTPS on port 443. Environment proxies, cookies, referrers, OS credentials and client-supplied headers are not inherited. NAT64/tunnel and other special ranges are conservatively refused; private/local provider endpoints are unsupported.

## Example and invocation

`network-echo` is a WASI-only SDK example. Its manifest declares `httpbin.org`; the code sends the complete reviewed synthetic input to that public echo service and suggests the echoed link. Use synthetic links only. Build/sign it with the same packer and combined MIT/Go notices as the API 1 example; never ship the generated private key. `network-probe` is an original abuse-test fixture, not an end-user provider. Neither example runs automatically.

A network-capable resolution posts `{id,url,networkApproved:true,digest}` to `/api/addons/resolve`. The digest must match the currently installed signed package; approval is per invocation. The SDK's legacy `Resolve` method grants no network access. `ResolveApproved` accepts the explicit network/digest approval. There is no generic network proxy or remote package-install endpoint.

Hosted validation and any later live-provider acceptance must be read back separately from this local evidence. OS-enforced worker RSS containment remains outstanding; the existing 128 MiB Go target is soft and is not upgraded by this API.
