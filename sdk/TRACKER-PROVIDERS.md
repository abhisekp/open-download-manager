# Signed tracker-provider add-ons

SDK API 2 now supports `tracker-provider` alongside `url-resolver`. A provider fetches its signed `feed_url` and returns suggestions. Installing, enabling or fetching never adds downloads, contacts suggested trackers, changes tracker membership or starts seeding. Use the existing public-torrent tracker review separately to apply chosen URLs; private/unknown-metadata protections remain in force.

`sdk/examples/newtrackon` is original MIT code for `https://newtrackon.com/api/live`. Build it with `GOOS=wasip1 GOARCH=wasm go build`, then use the existing signed-package CLI and include the application MIT license plus the compiled Go standard-library notices. Never put the private package key into source or distribution archives. The built-in tracker feed remains available independently.

The signed manifest requires API 2, capability `tracker-provider`, a fixed HTTPS port-443 `feed_url`, 1–16 exact `input_hosts`, and 1–16 exact `network_hosts`. The feed must belong to both declarations. `output_hosts` must be empty: tracker suggestions can describe other hosts, which are reviewed separately before any tracker contact. Feed URLs are public package metadata; do not embed credentials or private query tokens. Credentials/fragments/whitespace in the feed URL are refused. URL-resolver manifests cannot declare a feed URL.

The owner-only POST `/api/addons/trackers` accepts `{id,networkApproved:true,digest}`. The digest must match the installed, enabled, reviewed package; each fetch requires fresh approval. An input `url` is refused, so no user download link or torrent identifier is passed to this operation. Worker stdin contains `{api:2,operation:"trackers",url:<signed feed URL>}`. The module can use the same bounded `odm.http_get` ABI as other API 2 modules. Public DNS/IP pinning, no redirects/proxy/cookies/account credentials, response/call limits, timeouts and isolation remain unchanged; see [NETWORK.md](NETWORK.md).

Worker stdout is exactly `{"trackers":["udp://tracker.example:6969/announce", "https://tracker.example/announce"]}`. An empty array is valid. The host accepts at most 128 suggestions and a 256 KiB response, deduplicates exact URLs and refuses the whole response for an invalid member. Schemes are HTTP/HTTPS/UDP; UDP requires a valid explicit port. Credentials, fragments, whitespace/control characters and URLs over 2,048 bytes are refused. Suggested names are not DNS-resolved by this operation, and no suggestion is contacted. `urls` responses are only for URL resolvers; invoking the wrong capability is refused.

The Extensions page shows the signed feed and provider hosts before install, then an enabled-provider selector, per-fetch permission, result count, package fingerprint and a read-only list. Copy chosen suggestions into the public torrent's tracker controls for their separate review. Each fetch, provider change, package update or disabled/uninstalled provider clears the approval. Updates retain the existing disabled-by-default lifecycle.

Tests cover signed manifest restrictions, strict response schemas/URL/count validation, atomic refusal, empty feeds, real isolated child execution, wrong-capability refusal, disabled/updated/uninstalled packages, exact-digest approval, owner/Origin/input boundaries and the original newTrackon module with a private TLS feed fixture. Live provider behavior and hosted results are recorded separately from fixture evidence. OS-enforced worker RSS limits, event/UI contributions and automatic update distribution remain pending.

Local live acceptance on 2026-11-22: the original signed newTrackon module returned 82 suggestions through the actual owner UI and isolated child; approval reset after fetching, no transfers/torrents were created and no browser JavaScript errors were observed. The result count is time-dependent. The private TLS fixture remains the deterministic CI test.
