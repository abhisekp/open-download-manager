# Native BitTorrent

ODM integrates Rain v2.5.1 in its own process, with an attributed [local runtime compatibility patch](../internal/raincompat/ODM-PATCHES.md). Magnet links and HTTP(S) URLs ending in `.torrent` route to this engine; the Add dialog also accepts a local `.torrent` metadata file. Torrent transfers do not use aria2 and work when aria2 is absent. Native HTTP/HTTPS also work without aria2; FTP/SFTP require the optional engine.

State lives in `torrents.db` under the selected application data directory. Each torrent downloads into its own subdirectory below the selected download folder. Metadata imports are limited to 4 MiB and unsafe path components are rejected; magnet metadata also uses Rain's storage/path validation. DHT and peer exchange are disabled. The engine listens for torrent peers, so normal OS firewall/network policy applies. No automatic firewall rule is installed. Torrents stop after download completion by default. [Reviewed bounded seeding](SEEDING.md) can share completed files for an explicitly approved duration; file selection/priorities remain work in progress. [Separate live native download/upload limits](TORRENT-BANDWIDTH.md) persist across restarts and are shared by existing peers and webseeds.

Rain reports active byte totals as zero after stopping even when its persisted verified-piece bitfield is complete. ODM normalizes a complete verified-piece count to total bytes. Partial paused-progress counters may be less detailed than active counters. No completed state is inferred from downloaded network bytes alone.

Native tests construct original fixture metadata and run a seed and download client on loopback. They verify a real peer transfer, metadata exchange from a magnet, file-byte integrity, persistence after closing/reopening the native session, and rejection of unsafe imported metadata. No public swarm was contacted. `scripts/native_mode_test.py` verifies application startup, native HTTP transfer and torrent import with a deliberately missing aria2 path. Public/private swarm interoperability, BitTorrent v2/hybrid metadata and platform-specific firewall UX remain unverified. Private tracker-edit protection is tested separately below.

## Tracker review and additions

Select a native torrent and open **Trackers** to inspect its persisted tracker URLs. Public torrents with verified nonempty metadata can receive up to 32 reviewed URLs per request, capped at 128 total trackers. Choose HTTP, HTTPS or UDP URLs; UDP requires a valid port. Credentials in URL authority, fragments, whitespace, control characters, oversized URLs and unsupported schemes are rejected. The entire input list is validated before additions begin. Existing URLs are retained and duplicates are skipped.

Fetching newTrackon in Extensions has its own network permission. In a public torrent, **Review fetched trackers** copies up to 32 results into the review field; it does not add or contact them. The user must separately approve the exact URLs and choose **Add reviewed trackers**. Editing a URL clears that approval. New trackers can observe the torrent info hash and the user's network address. Private torrents are read-only, and magnets awaiting verified metadata cannot receive additions. The private flag is checked by the backend against native statistics and actual metadata; a client cannot override it.

The existing UI bearer/Host/Origin guard protects `GET /api/torrent-trackers?gid=…` and `POST /api/torrent-trackers` with `{gid,urls,approved:true}`. Browser pairing tokens and WASI add-ons do not gain access. Additions, removals, import quota checks and engine closure are serialized to prevent edit/removal races. A run-loop barrier precedes metadata reads and completes tracker changes before another edit.

Tracker edits are temporarily refused while files are being allocated or verified, even after metadata arrives. Wait until preparation finishes or pause the torrent. Rain starts newly added announcers immediately during preparation; without this lifecycle guard their peer-port read can race with listener startup. Stable downloading/seeding or stopped/stopping phases permit edits under ODM's lifecycle mutex. Regression checks cover every allowed/refused phase and repeated concurrent edits/removal; no timer or rerun is used as a substitute for this guard.

Rain saves each tracker independently. A storage failure returns the successfully added prefix and the remaining count; earlier additions are retained, not rolled back. The UI reports partial failure and requires another review. Paused public torrents can also replace or remove their complete tracker list after reviewing the exact current and replacement lists. Replacement is persisted in one transaction before active assignment; failed writes leave the old list intact. Stale edits are refused, the torrent stays paused, and new trackers are not contacted until explicit resume. A blank reviewed replacement removes all trackers and can prevent peer discovery. This requires fully Stopped state, unlike additions; private and unknown-metadata protection remains unchanged. The API uses action="replace", expected:[current URLs], urls:[replacement URLs], approved:true, bounded to 128 URLs per list and 544 KiB. Browser tests cover review, edit revocation, actual replacement/removal and refresh locking. Rich tracker status and file-priority controls remain open; bandwidth and seeding policies are documented separately.

Regression tests cover permission refusal, private/unknown-metadata protection, full prevalidation, duplicates, concurrent edits/removal, simulated partial storage failure, real local tracker traffic, unchanged info hashes, paused-state inspection and restart persistence. The browser flow was exercised with actual additions and private/unknown-metadata UI gating. The fetched-feed handoff used a mocked external feed and real native tracker additions; it is not evidence of a fresh live newTrackon request.

Rain is MIT licensed. One old transitive helper module lacked a license text in its pinned source. ODM replaces the narrow required API surface with original MIT code in `internal/nettoolscompat`: compact IPv4/IPv6 peer address encoding and bounded per-host throttling. This replacement is tested separately; it does not claim to implement the upstream helper's unused tunnel API. DHT remains disabled. Dependency license notices are generated from actual build dependencies with `scripts/notices.py`.

Hosted race detection subsequently exposed an independent shutdown bug: a tracker announcement worker could read torrent piece state after the announcer loop had closed. The runtime compatibility patch waits for in-flight workers after the loop ends and before owner state is cleared. Its deterministic blocked-snapshot regression fails against the original implementation and passes against the patch; repeated real concurrent tracker edits/removal and full local race checks also passed. Exact upstream runtime file hashes, reviewed patch hashes and the upstream MIT license are retained; CLI assets and upstream test fixtures are not copied. Both core/release validation and native preparation verify the source hash manifest. This is not evidence that every upstream test or public swarm has passed.

The UI and authenticated API maintain a unified transfer list, but native torrent lifecycle and persistence are separate from HTTP transfers. A saved torrent database is not an aria2 session file, and neither should be edited while the application is running.

Payload writes also use [rooted destination protection](TORRENT-STORAGE.md): existing links and size/type conflicts are refused, hard links are checked at open, and conflicting original files are kept instead of resized. Safe create/resume and native-engine recovery-message tests pass locally; platform symlink acceptance is tracked separately.
