# Native BitTorrent

ODM integrates Rain v2.5.1 in its own process. Magnet links and HTTP(S) URLs ending in `.torrent` route to this engine; the Add dialog also accepts a local `.torrent` metadata file. Torrent transfers do not use aria2 and work when aria2 is absent. Native HTTP/HTTPS also work without aria2; FTP/SFTP require the optional engine.

State lives in `torrents.db` under the selected application data directory. Each torrent downloads into its own subdirectory below the selected download folder. Metadata imports are limited to 4 MiB and unsafe path components are rejected; magnet metadata also uses Rain's storage/path validation. DHT and peer exchange are disabled. The engine listens for torrent peers, so normal OS firewall/network policy applies. No automatic firewall rule is installed. Torrents stop after download completion; seeding controls, file selection/priorities, and native bandwidth-limit controls remain work in progress.

Rain reports active byte totals as zero after stopping even when its persisted verified-piece bitfield is complete. ODM normalizes a complete verified-piece count to total bytes. Partial paused-progress counters may be less detailed than active counters. No completed state is inferred from downloaded network bytes alone.

Native tests construct original fixture metadata and run a seed and download client on loopback. They verify a real peer transfer, metadata exchange from a magnet, file-byte integrity, persistence after closing/reopening the native session, and rejection of unsafe imported metadata. No public swarm was contacted. `scripts/native_mode_test.py` verifies application startup, native HTTP transfer and torrent import with a deliberately missing aria2 path. Public/private swarm interoperability, BitTorrent v2/hybrid metadata and platform-specific firewall UX remain unverified. Private tracker-edit protection is tested separately below.

## Tracker review and additions

Select a native torrent and open **Trackers** to inspect its persisted tracker URLs. Public torrents with verified nonempty metadata can receive up to 32 reviewed URLs per request, capped at 128 total trackers. Choose HTTP, HTTPS or UDP URLs; UDP requires a valid port. Credentials in URL authority, fragments, whitespace, control characters, oversized URLs and unsupported schemes are rejected. The entire input list is validated before additions begin. Existing URLs are retained and duplicates are skipped.

Fetching newTrackon in Extensions has its own network permission. In a public torrent, **Review fetched trackers** copies up to 32 results into the review field; it does not add or contact them. The user must separately approve the exact URLs and choose **Add reviewed trackers**. Editing a URL clears that approval. New trackers can observe the torrent info hash and the user's network address. Private torrents are read-only, and magnets awaiting verified metadata cannot receive additions. The private flag is checked by the backend against native statistics and actual metadata; a client cannot override it.

The existing UI bearer/Host/Origin guard protects `GET /api/torrent-trackers?gid=…` and `POST /api/torrent-trackers` with `{gid,urls,approved:true}`. Browser pairing tokens and WASI add-ons do not gain access. Additions, removals, import quota checks and engine closure are serialized to prevent edit/removal races. A run-loop barrier precedes metadata reads and completes tracker changes before another edit.

Rain saves each tracker independently. A storage failure returns the successfully added prefix and the remaining count; earlier additions are retained, not rolled back. The UI reports partial failure and requires another review. Removing/replacing trackers, atomic replacement/rollback, richer status and native bandwidth/seeding/file-priority controls remain open.

Regression tests cover permission refusal, private/unknown-metadata protection, full prevalidation, duplicates, concurrent edits/removal, simulated partial storage failure, real local tracker traffic, unchanged info hashes, paused-state inspection and restart persistence. The browser flow was exercised with actual additions and private/unknown-metadata UI gating. The fetched-feed handoff used a mocked external feed and real native tracker additions; it is not evidence of a fresh live newTrackon request.

Rain is MIT licensed. One old transitive helper module lacked a license text in its pinned source. ODM replaces the narrow required API surface with original MIT code in `internal/nettoolscompat`: compact IPv4/IPv6 peer address encoding and bounded per-host throttling. This replacement is tested separately; it does not claim to implement the upstream helper's unused tunnel API. DHT remains disabled. Dependency license notices are generated from actual build dependencies with `scripts/notices.py`.

The UI and authenticated API maintain a unified transfer list, but native torrent lifecycle and persistence are separate from HTTP transfers. A saved torrent database is not an aria2 session file, and neither should be edited while the application is running.
