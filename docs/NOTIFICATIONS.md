# Desktop download notifications

The native desktop shell provides **Settings → Notify when downloads finish or fail**. It defaults to off. Enabling it permits ODM to send silent, generic completion/failure counts to the operating system while ODM is running, including while its window is hidden. Clicking a notification shows the existing downloads window. No file name, path, source URL, torrent name or error details are included. OS notification history may retain these generic counts under its own settings.

The preference is stored in `notifications.json` in the Electron profile (the custom data directory's `desktop-profile` when supplied). Saves use a synced, exclusive temporary file and replacement before applying the new preference. Invalid/oversized/nonregular settings are retained and the menu option is disabled; they never interrupt downloads. A failed save retains the previous setting and displays an error. No server, account, telemetry or browser permission is added.

Only newly observed transitions to complete/error are announced. The first successful snapshot after startup or enabling establishes a silent baseline, so opening ODM does not replay retained history. A retry that fails again can produce a new notice. Per-poll results are combined into one summary; the shell retains at most one live notification object. The authenticated loopback poll runs every five seconds only while enabled, with a three-second deadline, no redirects, a 2 MiB response limit and 2,048-row bound. Failed reads retain the previous baseline. Disabling or quitting aborts the poll, clears its timer, closes live notifications and invalidates late responses. No polling overlaps in ordinary operation.

This requires a usable operating-system notification service. Unsupported systems show a disabled option. Windows portable candidates do not yet install an application shortcut/notification identity; Linux desktop services and macOS notification permissions can also suppress banners. `isSupported()` alone does not prove display. System quiet/focus modes may hide notifications. Publisher signing, installers, OS permission troubleshooting and actual banner/click checks on installed systems remain acceptance work. No claim is made that these development candidates deliver notifications on every desktop.

Tests cover saved opt-in/out, damaged settings preservation, write failure, startup suppression, aggregation, repeat failure after retry, stale-request cancellation, status/OS failure isolation, bounded real HTTP reads and redirect refusal. Source and packaged native smoke tests also exercise the menu and real completed-transfer routing when the host reports support, without claiming OS banner display.

Official API and platform requirements: [Electron Notification](https://www.electronjs.org/docs/latest/api/notification) and [platform notification requirements](https://www.electronjs.org/docs/latest/tutorial/notifications), checked 2026-11-20.
