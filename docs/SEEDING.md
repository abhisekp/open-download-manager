# Reviewed, bounded torrent seeding

Downloads stop on completion by default. On a completed, fully paused native torrent, open **Seeding policy**, choose 1–1440 minutes, approve sharing its files with peers, then start. Peers receive the torrent's downloaded content and can see the user's network address; existing tracker/privacy restrictions and the shared upload cap remain in force. This also works with private torrents using their existing trackers, without enabling public discovery or changing tracker membership.

Changing duration clears approval. Active uploads appear as **Seeding**, with upload speed, and can be paused or stopped. **Stop sharing and clear deadline** cancels the saved sharing choice. Removing a transfer also closes its peers and retains its downloaded files.

The native database saves the absolute UTC deadline and intended started state in the same transaction before sharing starts. A restart may resume an approved session only within its original deadline; it never extends the approved duration. An expired session stays stopped even if the process died while sharing. An ordinary Resume after expiry retains stop-on-complete behavior. Expiry is checked by the run-loop's one-second ticker and stops peers even if the state write fails. These times depend on the operating-system clock; OS suspension/process scheduling and tracker stop messages are not exact real-time guarantees.

An unsuccessful start/save leaves the previous choice active. Stop always closes runtime sharing even if saving fails, and reports that the previous saved deadline may resume after a later restart. This distinction is necessary when durable storage is unavailable; the app does not claim that an unsuccessful disk write persisted revocation. Original deadline records are retained on invalid-state recovery rather than silently replaced.

Owner-only `GET /api/torrent-seeding?gid=…` returns `{until,ready,active}`. A POST requires `{gid,minutes,approved}`; positive minutes require explicit approval and a complete paused torrent. Zero stops without new approval. Input is bounded to 1 KiB and protected by existing bearer/Host/Origin checks. Browser pairing tokens and WASI add-ons gain no sharing permission.

Acceptance uses original loopback fixtures: real peer upload with exact byte comparison, runtime deadline shutdown, future-deadline restart without extension, expired crash-state refusal, no expired tracker announcement, failed-save preservation and stop behavior, owner/Origin/consent refusal, and real browser controls. `scripts/seeding_integration.py` additionally kills an actual sharing app process, waits through its one-minute deadline and restarts it, verifying no sharing or repeated source request and unchanged downloaded bytes. Hosted results remain separate from local test evidence. Ratio policies, per-torrent upload budgets and broader public/private swarm acceptance remain open.
